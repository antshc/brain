# Project Management Documentation Catalog

A practical set of project-management documents that complements architecture documentation such as arc42.

| Document | Purpose |
| --- | --- |
| **Project Charter / Project Brief** | Why the project exists, objectives, scope, sponsor, and success criteria. |
| **Roadmap / Milestone Plan** | Major phases, releases, target dates, dependencies, and sequencing. |
| **RAID Log** | Tracks risks, assumptions, issues, and dependencies. |
| **Stakeholder Map** | Identifies stakeholders, influence, responsibilities, and communication needs. |
| **RACI / Ownership Map** | Defines who is Responsible, Accountable, Consulted, and Informed. |
| **Decision Log** | Records project-level decisions that are not necessarily architecture decisions. |
| **Change Log / Change Requests** | Tracks scope, schedule, budget, or requirement changes and their impact. |
| **Dependency Map** | Documents dependencies on teams, systems, vendors, platforms, and external approvals. |
| **Release / Readiness Checklist** | Verifies product, engineering, QA, security, operations, and support readiness. |
| **Status Report** | Summarizes progress, milestone health, blockers, decisions needed, and next steps. |
| **Communication Plan** | Defines communication cadence, audience, channels, and reporting expectations. |
| **Resource / Capacity Plan** | Tracks team availability, skills, bottlenecks, and required external support. |
| **Budget / Cost Tracking** | Tracks forecast, actuals, and relevant vendor or cloud costs. |
| **Requirements / Scope Baseline** | Defines capabilities, business processes, functional requirements, and acceptance criteria. |
| **Business Process / Scenario Documentation** | Describes how the system supports business outcomes and key operational scenarios. |
| **Quality / NFR Tracking** | Tracks performance, availability, security, compliance, operability, and other non-functional requirements. |
| **Migration Plan** | Defines how an existing system, platform, data set, or workflow will be replaced or evolved. |
| **Rollout / Adoption Plan** | Plans pilots, migration waves, training, communication, and adoption. |
| **Operational Readiness Plan** | Covers monitoring, support, runbooks, ownership, incident response, and production readiness. |
| **Lessons Learned / Retrospective** | Captures what should change in the next phase, release, or project. |
