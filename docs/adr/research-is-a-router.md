# Research is a router; only Research spawns its route agents

Research Wayfinder charts or resumes a map in the caller's session, preserving destination confirmation, exact ticket approvals, dependencies, root fog and user-controlled proof integration. Shared Wayfinder operations belong to the GitHub skill; Git owns branch/worktree/commit mechanics. Research owns incremental synthesis and performs no automatic push, PR, session-base merge or Confluence publication. It resolves interview lookups and frontier research topics through the existing Frame, Routing and Spawning agents pipeline, without recursive Research calls or a new agent role. Independent frontier topics may run in parallel. Concepts remain in architecture-records define-concept.

For standalone evidence questions, Research first frames each question at the harness root: it reads the contract documents, resolves targets and `graphify-out/` coverage, and rephrases the question in `GLOSSARY.md` terms. It then routes each independent question to How, Why, Cloud, or Web, loads that route's playbook, and spawns the route's agents: the registered `hunty` agent (codebase evidence), `explainy` (How explanation), `whyy` and `composy` (Why investigation and synthesis), `cloudy` (AWS/Azure), and `weby` (other external sources). Each prompt-file agent lives under `research/agents/`, filled by the router and run in a `general-purpose` worker with the role's model from the `subagents` skill. `hunty` is the exception: a registered wf plugin agent (`agents/hunty.agent.md`, pinned model) that loads the standalone `hunty` skill, which owns lookup routes `rg`, `lsp`, `graphify-path`, `graphify-find`, `nuget`, the Graphify scripts and the read-only contract. Research has no Explore route; any caller spawns `hunty` directly for a pure lookup and receives its verdict inline. Agents, including `hunty`, never spawn subagents or load `research`; they return gaps to the caller. Callers load Research in their own session, never inside a wrapper subagent, and never spawn prompt-file route agents directly. Applies only to the `research` skill and the `hunty` agent and skill.

The request text is the only input: Research discovers questions, route, Why depth, targets, framing, and destination from it. Wayfinder keeps its authoritative map and all unknowns/risks in a GitHub root issue with approved research/experiment sub-issues. Owned `wayfinder/`, `research/` and `prove/` worktrees retain the living `docs/ongoing/<slug>-research.md`, topic reports and reproducible proof. Verified research integrates automatically; exact proof payloads require explicit approval. It persists `hunty` lookup verdicts as topic reports; standalone delivery stays unchanged. Other reports save to the agent session workspace (`files/research/`) with links presented to the user, or to a location the request names; pure lookups return inline. `hunty` uses local checkouts only, Graphify for covered relationships, and the NuGet tactic for restored package-cache evidence; missing local checkouts or refs are blockers, never filled by remote lookup, clone, or fetch.

## Alternatives considered

- **Explore route spawning a private `hunty` prompt file** — rejected: every lookup paid the full Research load and Frame cost, and callers could not reach exploration without the router; a registered agent backed by its own skill gives Explore-agent ergonomics while the no-subagent rule prevents the nesting that sank `hunter`.
- Registering `hunter` as a plugin agent that spawned further workers. Callers inside workers spawned it again, nesting subagents; `hunty` forbids spawning and owns its request contract in one skill.
- Folding lookups into How. Callers such as Design Grill need raw cited verdicts without an explanation or report file; `hunty` returns exactly that.
- Generic `subagents` Dispatch for route workers. Dispatch hid which prompt and model each route used; per-route prompt files make the spawn explicit while `subagents` keeps only model selection.
- Registering each route agent. Prompt files keep explanation, rationale, cloud and web agents private to Research, so other skills cannot bypass routing; only codebase lookup is general enough to register.
