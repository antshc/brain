# Research is a router; only Research spawns its route agents

Research Define charts or resumes a map in the caller's session, preserving destination/map confirmation, dependencies, fog and user-controlled experiments. It resolves interview lookups and frontier research topics through the existing Frame, Routing and Spawning agents pipeline, without recursive Research calls or a new agent role. Independent frontier topics may run in parallel. Concepts remain in architecture-records define-concept.

For standalone evidence questions, Research first frames each question at the harness root: it reads the contract documents, resolves targets and `graphify-out/` coverage, and rephrases the question in `GLOSSARY.md` terms. It then routes each independent question to Explore, How, Why, Cloud, or Web, loads that route's playbook, and spawns the route's agents: `hunty` (How evidence, lookups, Graphify and NuGet tactics), `explainy` (How explanation), `whyy` and `composy` (Why investigation and synthesis), `cloudy` (AWS/Azure), and `weby` (other external sources). Each agent is a prompt file under `research/agents/`, filled by the router and run in a `general-purpose` worker with the role's model from the `subagents` skill. Agents never spawn subagents or load `research`; they return gaps to the router. Callers load Research in their own session, never inside a wrapper subagent, and never spawn route agents directly. A pure lookup uses Explore: one `hunty` pass per lookup, verdicts returned inline to the calling agent.

The request text is the only input: Research discovers questions, route, Why depth, targets, framing, and destination from it. Define saves maps under `docs/ongoing/` and topic reports under `docs/research/`, or explicit caller destinations; it persists Explore verdicts as topic reports and presents checkpoint tables and map/report links. Other reports save to the agent session workspace (`files/research/`) with links presented to the user, or to a location the request names; pure lookups return inline. `hunty` uses local checkouts only, Graphify for covered relationships, and the NuGet tactic for restored package-cache evidence; missing local checkouts or refs are blockers, never filled by remote lookup, clone, or fetch.

## Alternatives considered

- Registering `hunter` as a plugin agent that many skills spawned directly. Callers inside workers spawned it again, nesting subagents, and every caller duplicated the Explore request contract.
- Folding lookups into How. Callers such as Design Grill need raw cited verdicts without an explanation or report file; a separate Explore route returns exactly that.
- Generic `subagents` Dispatch for route workers. Dispatch hid which prompt and model each route used; per-route prompt files make the spawn explicit while `subagents` keeps only model selection.
- Registering each route agent. Prompt files keep the agents private to Research, so other skills cannot bypass routing.
