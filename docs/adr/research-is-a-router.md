# Research is a router; only Research spawns its route agents

Research Wayfinder charts or resumes a map in the caller's session, preserving destination confirmation, exact ticket approvals, dependencies, root fog and user-controlled proof integration. Shared Wayfinder operations belong to the GitHub skill; Git owns branch/worktree/commit mechanics. Research owns incremental synthesis and performs no automatic push, PR, session-base merge or Confluence publication. It resolves interview lookups and frontier research topics through the existing Frame, Routing and Spawning agents pipeline, without recursive Research calls or a new agent role. Independent frontier topics may run in parallel. Concepts remain in architecture-records define-concept.

For standalone evidence questions, Research first frames each question at the harness root: it reads the contract documents, resolves targets, and rephrases the question in `GLOSSARY.md` terms. It then routes each independent question to How, Why, or Web, loads that route's playbook, and spawns the route's workers: the registered `codebase` agent (codebase evidence), `explainy` (How explanation), `whyy` (Why anchor and per-source investigation: source control, Jira, Confluence), and `weby` (external primary sources, including AWS/Azure). Each role's prompt is a section of its route playbook, filled by the router and run in a `general-purpose` worker with the role's model from the `subagents` skill. Workers write the answer; the router presents it with light edits and synthesizes Why investigator outputs itself, without a separate synthesizer. `codebase` is the exception: a registered wf plugin agent (`agents/codebase.agent.md`, default model) built on the VS Code Explore agent prompt, with its own deployable/multi-repo targeting, terminal search, NuGet inspection and read-only rules. Research has no Explore route; any caller spawns `codebase` directly for a pure lookup and receives its verdict inline. Agents, including `codebase`, never spawn subagents or load `research`; they return gaps to the caller. Callers load Research in their own session, never inside a wrapper subagent, and never spawn route workers directly. Applies only to the `research` skill and the `codebase` agent.

The request text is the only input: Research discovers questions, route, Why depth, targets, framing, and destination from it. Wayfinder keeps its authoritative map and all unknowns/risks in a GitHub root issue with approved research/experiment sub-issues. Owned `wayfinder/`, `research/` and `prove/` worktrees retain the living `docs/ongoing/<slug>-research.md`, topic reports and reproducible proof. Verified research integrates automatically; exact proof payloads require explicit approval. It persists `codebase` lookup verdicts as topic reports; standalone delivery stays unchanged. Other reports save to the agent session workspace (`files/research/`) with links presented to the user, or to a location the request names; pure lookups return inline. `codebase` uses local checkouts only and the restored NuGet package cache; missing local checkouts or refs are blockers, never filled by remote lookup, clone, or fetch.

## Alternatives considered

- **Explore route spawning a private lookup prompt file** — rejected: every lookup paid the full Research load and Frame cost, and callers could not reach exploration without the router; a registered agent gives Explore-agent ergonomics while the no-subagent rule prevents the nesting that sank `hunter`.
- Registering `hunter` as a plugin agent that spawned further workers. Callers inside workers spawned it again, nesting subagents; `codebase` forbids spawning and owns its rules in one agent file.
- Folding lookups into How. Callers such as Design Grill need raw cited verdicts without an explanation or report file; `codebase` returns exactly that.
- Generic `subagents` Dispatch for route workers. Dispatch hid which prompt and model each route used; per-role playbook sections make the spawn explicit while `subagents` keeps only model selection.
- Registering each route agent. Playbook-section prompts keep explanation, rationale and web workers private to Research, so other skills cannot bypass routing; only codebase lookup is general enough to register.
- Separate Cloud route and `cloudy` agent. Provider docs, APIs and read-only CLI are primary sources; Web covers them with provider references loaded only for AWS or Azure.
- Separate `composy` synthesizer and full source roster for Why. Upstream pstack `why` answers from the commit/PR record; investigators tier their own claims and the router presents them, keeping source control, Jira and Confluence only.
- `hunty` agent plus a separate `explore-codebase` skill with route table, pinned low-effort model and Graphify scripts. Two files described one job, and Graphify added an index to build and trust-gate; one `codebase` agent based on the VS Code Explore prompt keeps only rules the base prompt lacks: deployable and multi-repo targeting, terminal search, and NuGet.
