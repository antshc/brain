# Ralph is agent-agnostic

Ralph knows its agent roster but nothing about what the agents contain. It names the crew at the launch site, and encodes the ordering, gate, and unavailability policy between them — but carries no assumption about an agent's internals, prompts beyond the documented handoff sections, or toolchain, and could launch any agent that honors the same invocation-directory contract and five-field report format.

- **OS agnostic** `ralph` skills and agents must not embed OS-specific shell syntax (bash-only or PowerShell-only) in their commands or helper scripts. A step prefers a bare, pure cross-platform CLI invocation (e.g. `gh`, `git`) written inline in the instruction; only once the logic exceeds a single pure command — branching, parsing, multi-step state — is it moved to a Python script, so the same instruction runs unmodified on Linux, macOS, and Windows, instead of asking the agent to pick and maintain a per-OS variant.
- **Resolve at the edge**: ambient location (`HARNESS_REPO_PATH`, `CODEBASE_REPO_PATH`) is discovered exactly once by the entry-point skill (`resolve-harness`/`init-harness`/`ralph:dev`/`ralph:fix`/`ralph:address`) and passed only to components that require it, through trusted channels such as Codey's `## HARNESS` section and worktree-skill arguments. Chorey needs no ambient path: its invocation directory is the workspace, installed skills expose its rules and gotchas capabilities, and Ralph stages the incoming change set with `git add` before invoking it — Chorey receives no trusted input beyond cwd.
- **Contract, not internals**: Ralph depends only on what an agent *exposes* — it runs in its invocation directory and returns the five-field report. How it implements, verifies, or reviews is opaque. An agent Ralph cannot invoke is substituted or skipped per its documented policy, and Ralph synthesizes the missing five-field report itself so downstream steps never read an absent `STATUS`.
- **Which agent is a crew question**: once the roster grew past one implementer, Ralph chooses from the installed crew agent descriptions for the task; unmatched work uses `general-purpose`. Chorey keeps change-set and aggregate-stack discovery internal through `chorey-diff`, then passes the manifest stacks to `/crew-chore` for rule loading.

## Considered Options

- **Resolve agents through a role indirection layer** (`implementation agent`/`review agent` names read from configuration) — rejected when the roster held one implementer. The expanded roster is selected from agent descriptions at the caller; Chorey selects its own review rules without an additional routing skill.
