# Crew

Three implementation agents cover Python, AI authoring, and .NET: `codey-py`, `codey-ai`, and `codey-dotnet`. `chorey` reviews behavior-preserving cleanup. There is no base `codey` agent.

- `to-crew` and `ralph:dev` choose an implementation agent from the installed agents' descriptions, or `general-purpose` when none matches. `to-crew` mirrors `ralph:dev`'s per-task flow on a single task: stage Codey's changes, review them with Chorey, then close, comment on, or label the related issue from Codey's `STATUS`. Unlike `ralph:dev`, `to-crew` never commits — every change from both agents stays staged and uncommitted for the user. Chorey requires `/crew-chore`, passes it the aggregate stacks detected by `chorey-diff`, and uses an empty stack array to load every configured repository-local stack rule file.
- Each Codey agent owns input, implementation, focused verification, gotchas, and its five-field status report. The .NET agent traces the functional slice and tests its highest useful observable seam. Python and AI agents use compact flows.
- `chorey-diff` owns Chorey's staged/uncommitted change capture, manifest stack detection, and artifact cleanup. The caller (`ralph:dev`, `to-crew`) stages the incoming change set with `git add` before invoking Chorey; neither `chorey-diff` nor Chorey ever stages. Chorey's agent passes manifest stacks to `/crew-chore` and owns behavior-preserving review and scoped verification; cleanup that fails verification is left applied and reported as a finding, never reverted. Chorey's report is informational; Codey's `STATUS` gates follow-up handling.
- `init-crew` copies per-stack `.github/instructions/*.instructions.md` into the codebase repo, creates `/crew-chore` with per-stack rule files, and creates `/crew-memory` in the harness repo's `.github/skills/`. Existing repository rules are preserved and merged. Legacy `.crew/` files are ignored.
- `/crew-memory` owns its own persistent `## Gotchas` section; it passes the stored rules to `crew-gotchas`, which owns the shared rule-processing procedure. `chorey-diff` owns the temporary `bin/crew_diff/` review bundle; `crew-commit` owns post-task commits, used directly by the user. `ralph:dev` stages Codey's and Chorey's changes and makes its own single commit on an isolated worktree branch instead and never routes through `crew-commit`; `to-crew` never commits at all.

Codey runs in cwd and uses `/crew-memory` directly; callers do not pass its storage location. Chorey receives no trusted input beyond cwd, runs in cwd, and requires `/crew-chore` plus `/crew-memory` when available. `chorey-diff` detects the aggregate stacks, Chorey passes them unchanged, and the Chore skill loads the named stack rules or all configured rules for an empty array. The memory skill owns storage and passes only loaded rules to `/crew-gotchas`; an unavailable memory skill is a no-op. Applicable Copilot instructions are supplied automatically and need no explicit discovery step.

Every agent report has `STATUS`, `SUMMARY`, `FILES`, `GOTCHAS UPDATED`, and `NOTES`. For Codey, `complete` means the relevant checks passed or the requested state was already present, `partial` names persistent code errors, and `blocked` names a fundamental or environmental blocker. Chorey reports `complete` after a finished or unnecessary review, `failed` when applied cleanup could not be verified and remains applied, and `skipped` when invalid input or `/crew-chore` is unavailable.
