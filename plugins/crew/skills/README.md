# Crew

Crew ships `codey-py`, `codey-ai`, and `codey-dotnet` for implementation and `chorey` for behavior-preserving cleanup.

- `to-crew` and `ralph:dev` select the Python or AI specialist when relevant and use `codey-dotnet` for general coding. An unavailable selection falls back to `general-purpose`. `to-crew` mirrors `ralph:dev`'s per-task flow on a single task: stage Codey's changes, review them with Chorey, then close, comment on, or label the related issue from Codey's `STATUS`. Unlike `ralph:dev`, `to-crew` never commits — every change from both agents stays staged and uncommitted for the user. Chorey requires `/crew-chore`, passes it the aggregate stacks detected by `chorey-diff`, and uses an empty stack array to load every configured repository-local stack rule file.
- Each Codey agent owns input, implementation, focused verification, gotchas, and its five-field status report. Codey agents select a risk-based test strategy per changed behavior (failing reproduction for bugs, test-first for uncertain logic, characterization before refactors, contract-first for public contracts, test-after for clear features, existing checks for covered mechanical edits), never weaken a valid test to get green, and mark each check `passed`, `failed`, `unavailable`, or `not run`. `codey-dotnet` calls `testing-integrations` when narrower checks leave a concrete risk and uses the fastest configuration that exposes it. Python and AI agents use compact flows.
- `chorey-diff` owns Chorey's staged/uncommitted change capture, manifest stack detection, and artifact cleanup. The caller (`ralph:dev`, `to-crew`) stages the incoming change set with `git add` before invoking Chorey; neither `chorey-diff` nor Chorey ever stages. Chorey's agent passes manifest stacks to `/crew-chore` and owns behavior-preserving review and scoped verification; cleanup that fails verification is left applied and reported as a finding, never reverted. Chorey's report is informational; Codey's `STATUS` gates follow-up handling.
- `init-crew` copies per-stack `.github/instructions/*.instructions.md` into the codebase repo and creates `/crew-chore` with per-stack rule files. Existing repository rules are preserved and merged. Legacy `.crew/` files are ignored.
- `chorey-diff` owns the temporary `bin/crew_diff/` review bundle; `crew-commit` owns post-task commits, used directly by the user. `ralph:dev` stages Codey's and Chorey's changes and makes its own single commit on an isolated worktree branch instead and never routes through `crew-commit`; `to-crew` never commits at all.

`codey-dotnet` runs in CWD by default and validates an assigned worktree and branch when provided. `implement-spec` uses the same agent with ticket pointers, explicit authority to make one verified ticket commit, and a JSON result. Crew callers use the uncommitted delivery policy.

Codey and Chorey reports have `STATUS`, `SUMMARY`, `FILES`, `GOTCHAS`, and `NOTES`. For Codey, `complete` means the relevant checks passed or the requested state was already present, `partial` names persistent code errors, and `blocked` names a fundamental or environmental blocker. Chorey reports `complete` after a finished or unnecessary review, `failed` when applied cleanup could not be verified and remains applied, and `skipped` when invalid input or `/crew-chore` is unavailable. Gotchas are observed, reusable findings returned by the agent.
