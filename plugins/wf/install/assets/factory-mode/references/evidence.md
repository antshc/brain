# Evidence

## Select the evidence

- For current behavior, code location, design rationale, or read-only investigation, run Research.
- If reading cannot settle an observable uncertainty, *Load and follow the `prove` skill to confirm or refute the claim by executing a test, runnable prototype, GUI E2E check, or cloud experiment.* State the deciding observation and use the result to decide.
- For competing designs, follow the current route's design loop or hand off to the Design playbook. Ask about product or preference choices only when evidence cannot decide and the route calls for a human choice. Use the question tool with a recommended default when the owning route permits it.

## Research

*Load and follow the `research` skill to investigate the question and save cited findings.* Use How for current behavior and lookups, Why for rationale, and Web for outside evidence, including AWS/Azure.

Pass the original request verbatim. Add a grounded question with the repository or external target, subsystem or symbol, exact unknown, and expected evidence. Preserve the requested output and framing. Research owns source selection, specialists, and delegation.

Give each report an exact absolute path and base. Keep the user's explicit destination. Otherwise use `<repo-root>/tmp/factory-mode-<task-slug>/research/<question-slug>.md`. Name each report path when requesting several. Use the returned citations or report the concrete evidence gap.
