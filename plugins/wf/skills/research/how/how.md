# How

Investigate current-system behavior directly: frame → discover → trace → verify → explain → deliver. Apply Research's Read-only contract and Caller-owned destinations. Use the registered Local search and Evidence checklist; no evidence or synthesis dispatch.

## Workflow

1. **Frame.** Preserve question, targets/refs, framing, start, outcome and destination. State a bounded interpretation when needed. Done when question and observable outcome are explicit.
2. **Select depth.** Narrow → Concise, one focused pass. Cross-boundary/complex → Detailed, relevant boundaries/failures/edges. Explicit inspection → Full within scope, including runtime claims or blockers. Escalate on deciding conflicts/gaps; depth never means full-repository coverage. Done when depth matches requested proof.
3. **Discover.** Resolve local targets/contracts. Unknown ownership → inspect deployables, functional slices, triggers, candidate paths and boundaries with the Evidence checklist. Known narrow target combines discovery/tracing. Done when relevant owners/paths are cited or unresolved.
4. **Plan evidence.** Select Behavior, Flow, Data or focused checks; mix only outcome-relevant checks into one answer. Sequence dependent angles after discovery. Done when each angle has bounded scope and proof checks.
5. **Trace.** Apply the Evidence checklist directly with question, angle, targets/refs, depth and checks. Follow executing paths, selected providers, data, failures and handoffs; inspect restored packages when decisive. Keep a compact evidence index. Done when branches have cited outcomes, justified stops or named gaps.
6. **Verify.** Apply Inspection evidence and authorized runtime checks. Resolve material gaps directly. Cloud semantics/live values deciding the answer → load the registered Cloud resources and inspect directly. Blocked → preserve claim, consequence, blocker and exact next check. Done when deciding claims have evidence or explicit limits.
7. **Explain.** Write the answer directly using How report and caller framing. Lead with the answer and domain concepts; integrate deciding lens/provider/package findings once. Material gaps return to Verify. Done when the explanation follows the mechanism without inventing evidence.
8. **Validate and deliver.** Check How report, verify Mermaid rendering or name the rendering blocker, fix material defects and apply Caller-owned destinations. Done when one cited explanation is delivered or the evidence/destination blocker is named.

## Completion criteria

- Each scoped trigger/branch reaches a cited outcome, justified stopping boundary, or gap with consequence and next check.
- One explanation integrates deciding Behavior, Flow, Data and provider findings; static possibilities remain distinct from runtime observations.
- Framing and destinations match caller inputs; under Hunter the caller saves the returned final report.

Last, sweep original question and requested branches against evidence. Resolve omissions or report them; no complete-inspection claim with unaccounted scope.
