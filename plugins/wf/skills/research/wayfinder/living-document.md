# Living research reconciliation

Run after every integrated result, pause, human choice, approval and resume. Use [Research document](research-document.template.md) for structure, not as a replacement for existing content.

1. Read the latest integration-branch document and newly integrated evidence in full. Match supported conclusions, conflicts, unknowns and canonical source identities against the last reconciled evidence/HEAD. Verify paths and refs before using a result; pending proof is not integrated evidence.
2. Update matching subjects and sections in place. Preserve verified findings and human decisions; supersede only with stronger evidence and retain the reason/source. Avoid duplicate findings, references and outcome rows. Do not copy entire topic/proof reports into the living document.
3. Keep incomplete/conflicting claims in root Not yet specified and document Remaining work. Open questions / decisions holds human decisions and links to relevant root gaps; it is not a competing fog register. Mark unconfirmed conclusions **Not confirmed**; pending proof observations never become confirmed integrated outcomes.
4. *Load and follow the `writing-style` skill to apply clear, precise writing to technical docs* using **Write a bottom line**, loading its selected references in full, including `references/bottom-line.md`. Update Bottom line, What we did, Remaining work, Next steps and References so conclusions/actions match verification status. Keep detailed evidence independently readable.
5. Validate repository-relative links against existing integrated reports and prove every referenced file exists at the integration HEAD. From `docs/ongoing/`, use `../research/<slug>/<topic>.md` and `../prototype/<slug>/<experiment>/report.md`. Explicit destinations need equally valid links; never fabricate remote URLs for unpushed files.
6. Commit the document locally through shared Commit the document; record the last reconciled evidence/result identity and document HEAD outside disposable worktrees. A no-change rerun creates no commit. Then update child Result and root findings/fog through shared Update map or ticket, preserving concurrent edits. Clear only evidence-resolved or explicitly scoped-out entries; preserve IDs and supported resolution history.
7. Persist the first unconfirmed synchronization step on failure. On resume read back local and tracker state, then retry only that step. A merged result never merges twice; a committed conclusion never duplicates; a failed tracker update never loses verified local evidence.
