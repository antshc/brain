# Write sentences to the reader (Google developer style)

- Address the reader as "you" in the present tense; reserve "will" for future events.
- Name who does what. Use passive only when the actor is unknown or irrelevant.
- Write instructions as commands and facts as statements, never "should be done".
- Put the condition before the instruction, the common case before exceptions.
- Sound like a knowledgeable friend. Avoid buzzwords, figurative language, "please", "simply", "easy" and "quickly" in procedures.
- Avoid pre-announcements and consecutive sentences starting with the same phrase.
- Use descriptive link text, never "click here". Prefer local context over an unexplained link.
- Make headings carry the point in sentence case. Use verb phrases for tasks and noun phrases for concepts. Whole documents use one H1 and no skipped levels; references, templates and caller-required structures keep their owner's format.
- Number sequences; use bullets otherwise. Introduce lists with a complete sentence and keep items parallel.
- Use code font for code, bold for UI elements and serial commas. Drop "etc." and state when a list is partial.
